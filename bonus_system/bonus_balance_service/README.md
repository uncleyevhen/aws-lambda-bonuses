# Система бонусів з DynamoDB та синхронізацією в KeyCRM

## Огляд системи

Нова система бонусів вирішує проблему дублювання клієнтів в KeyCRM шляхом створення централізованого сховища балансів бонусів в AWS DynamoDB з подальшою синхронізацією даних в KeyCRM.

### Проблема, яку вирішуємо

- **Дублювання клієнтів**: В KeyCRM можуть створюватися дублікати клієнтів з одним номером телефону але різними email
- **Втрата бонусів**: При дублюванні клієнта його бонуси "губляються", оскільки зберігаються тільки у конкретного клієнта
- **Неконсистентність**: Різні дублікати мають різні баланси бонусів

### Рішення

1. **DynamoDB як основне сховище**: Всі баланси та історія операцій зберігаються в DynamoDB з номером телефону як ключем
2. **KeyCRM як дублікат даних**: KeyCRM тепер тільки дублює інформацію з DynamoDB для кожного клієнта
3. **Автоматична синхронізація**: При кожній операції дані синхронізуються з всіма дублікатами клієнтів в KeyCRM

## Архітектура системи

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   DynamoDB      │    │  Lambda          │    │    KeyCRM       │
│  (основне       │◄───│  Functions       │───►│  (дублікати     │
│   сховище)      │    │                  │    │   даних)        │
├─────────────────┤    ├──────────────────┤    ├─────────────────┤
│ phone_number    │    │ BonusOperations  │    │ Клієнт 1        │
│ active_bonus    │    │ BalanceChecker   │    │ Клієнт 2 (дубл) │
│ reserved_bonus  │    │ SyncService      │    │ Клієнт 3 (дубл) │
│ history         │    │ MigrationScript  │    │ ...             │
│ expiry_date     │    │                  │    │                 │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

## Компоненти системи

### 1. BonusBalanceManager (`bonus_balance_manager.py`)

Основний клас для роботи з DynamoDB. Забезпечує:

- **Атомарні операції** з балансами бонусів
- **Автоматичне управління терміном дії** бонусів (90 днів)
- **Повну історію транзакцій**
- **Нормалізацію номерів телефонів**

#### Структура даних в DynamoDB:

```json
{
  "phone_number": "+380123456789",
  "active_bonus": 150,
  "reserved_bonus": 30,
  "total_earned": 1000,
  "total_used": 200,
  "bonus_expiry_date": "2025-03-24",
  "transaction_history": [
    {
      "timestamp": "2025-01-15T10:30:00Z",
      "type": "earned",
      "amount": 100,
      "order_id": "ORDER123",
      "description": "✅ Виконано замовлення ORDER123: +100 бонусів"
    }
  ],
  "last_updated": "2025-01-15T10:30:00Z",
  "created_at": "2025-01-01T00:00:00Z"
}
```

### 2. BonusSyncService (`sync_service.py`)

Сервіс синхронізації між DynamoDB та KeyCRM:

- **Синхронізація в всі дублікати** клієнтів в KeyCRM
- **Копіювання повної історії** з DynamoDB в KeyCRM
- **Обробка нових клієнтів** з автоматичним копіюванням існуючої історії

### 3. EnhancedBonusOperations (`enhanced_bonus_operations.py`)

Розширений клас операцій з бонусами:

- **Операції спочатку в DynamoDB**, потім синхронізація в KeyCRM
- **Збереження зворотної сумісності**
- **Обробка помилок синхронізації**

### 4. EnhancedBalanceChecker (`enhanced_balance_checker.py`)

Lambda функція для перевірки балансу:

- **Основне джерело**: DynamoDB
- **Fallback**: KeyCRM (для зворотної сумісності)
- **Автоматичне очищення прострочених бонусів**

### 5. MigrationScript (`migration_script.py`)

Скрипт міграції існуючих даних:

- **Дедуплікація клієнтів** по номеру телефону
- **Консолідація балансів** та історії дублікатів
- **Безпечна міграція** з можливістю dry-run

## Установка та налаштування

### 1. Створення DynamoDB таблиці

```bash
aws dynamodb create-table \
  --table-name bonus-balances \
  --attribute-definitions \
    AttributeName=phone_number,AttributeType=S \
  --key-schema \
    AttributeName=phone_number,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region eu-north-1
```

### 2. Налаштування Lambda функцій

Додати до всіх Lambda функцій права доступу до DynamoDB:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Query",
        "dynamodb:Scan"
      ],
      "Resource": "arn:aws:dynamodb:eu-north-1:*:table/bonus-balances"
    }
  ]
}
```

### 3. Міграція існуючих даних

```bash
# Тестовий запуск
python migration_script.py --dry-run

# Реальна міграція
python migration_script.py
```

```python

    'description': '✅ Виконано замовлення: +100 бонусів'

    "+380123456789",
    active_bonus_delta=100,
    transaction=transaction

```

```python
}

    "+380123456789",
    active_bonus_delta=-50,
    reserved_bonus_delta=50,
    transaction=transaction
)
```

### Синхронізація з KeyCRM

```python

```

## Логіка роботи з дублікатами

### Сценарій 1: Новий клієнт

1. Клієнт робить замовлення
2. Створюється новий запис в KeyCRM
3. Система перевіряє чи існує номер телефону в DynamoDB
4. Якщо існує - копіює всю історію з DynamoDB в нового клієнта KeyCRM
5. Якщо не існує - створює новий запис в DynamoDB

### Сценарій 2: Існуючий клієнт (дублікат)

1. Клієнт з існуючим номером робить замовлення, але вказує інший email
2. Створюється новий клієнт в KeyCRM (дублікат)
3. Система знаходить номер телефону в DynamoDB
4. **Автоматично копіює всю історію** та поточний баланс в нового клієнта
5. Новий клієнт одразу має всі свої бонуси та історію операцій

### Сценарій 3: Операція з бонусами

1. Виконується будь-яка операція з бонусами (нарахування, резервування, використання)
2. **Спочатку оновлюється DynamoDB** (основне джерело правди)
3. **Потім синхронізуються всі дублікати** клієнтів в KeyCRM
4. Всі дублікати отримують однакові баланси та оновлену історію

## Переваги нової системи

### ✅ Вирішені проблеми

- **Немає втрати бонусів** при дублюванні клієнтів
- **Консистентні дані** у всіх дублікатах
- **Централізоване управління** балансами
- **Повна історія операцій** для кожного номера телефону

### 🚀 Додаткові можливості

- **Автоматичне очищення** прострочених бонусів
- **Атомарні операції** без race conditions
- **Fallback на KeyCRM** для зворотної сумісності
- **Детальне логування** всіх операцій
- **Масштабованість** завдяки DynamoDB

### 📊 Моніторинг

- Всі операції логуються в CloudWatch
- Метрики використання DynamoDB
- Статистика синхронізації з KeyCRM
- Моніторинг прострочених бонусів

## FAQ

**Q: Що станеться якщо DynamoDB буде недоступна?**
A: Система автоматично перемкнеться на роботу з KeyCRM (fallback режим)

**Q: Як обробляються конкурентні запити?**
A: DynamoDB забезпечує атомарність операцій через умовні оновлення

**Q: Чи можна скасувати міграцію?**
A: Так, старі дані в KeyCRM не видаляються, можна повернутися до старої системи

**Q: Скільки коштує DynamoDB для цієї системи?**
A: При режимі Pay-Per-Request вартість мінімальна (~$1-5/місяць для малих об'ємів)

**Q: Що робити з клієнтами без номерів телефонів?**
A: Такі клієнти залишаються в старій системі (тільки KeyCRM)
